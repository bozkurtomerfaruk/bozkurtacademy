# Exercise and grammar authoring

Every question needs feedback explaining its own grammatical trigger: the actual subject and verb form, required preposition/case, meaning clue or word-order constituents. Do not reuse a topic-level paragraph with only the correct answer substituted. Preserve useful existing reasoning and avoid stock instructions that bury it. Check incorrect multiple-choice and written submissions in the browser, including Enter submission, when changing feedback.

When adding an exercise topic at any level, also add its complete grammar lesson in the same task without asking the user separately. This is a standing user preference.

Use the exercise topic ID in data/<level>-grammar.json. Register a new level in data/grammar-index.json. The grammar list derives from data/catalog.json; do not maintain a separate topic list.

Write simple Turkish for a first-time learner, German examples with Turkish translations, progressing from simple to harder examples. Include useful accessible visual diagrams, at least five teaching sections, a summary and self-check, three FAQs, three relevant related topics, an exercise link, the existing author introduction and moderated name/email comment form. Large headings do not need final periods. Reuse the professional theme and dark-mode styles.

After adding or renaming exercise packages, run node scripts/build-search-index.mjs so the exercise search finds them (CI runs it with --check).

Word lists: questions may list their nouns in "vocab" (keys of data/sozluk.json: article + Turkish meaning, also shown in the German and English interface). Mark entries you are not sure about with "unsure": true; they stay hidden until the teacher sets "checked". After changing vocab or the dictionary, run node scripts/sozluk.mjs to refresh docs/sozluk-kontrol.csv and docs/sozluk-bekleyen.csv, the table of words not yet checked that the teacher reviews for each pull request (CI runs it with --check). Skip Turkish hints, German instructions, grammar terms (Subjekt, Kasus, Hauptsatz …), names and imperatives; a word like Essen or Morgen counts as a noun only after an article or preposition. Exam sets never show word lists.

End-of-level tests: data/seviye-sonu/<level>.json, linked from data/catalog.json with "levelExam". 30 questions per attempt with a fixed topic distribution; the pool needs at least twice as many questions per topic, each with four options and its own Turkish explanation (node scripts/check-level-exams.mjs). Results go to results with topic "seviye-sonu" and topicErrors; never store which questions were shown.

Children's game Artikel Evleri (#artikel-evleri, js/artikel-evleri.js): topics in data/cocuk/artikel-evleri.json list keys of data/sozluk.json (checked, not unsure, one article) with equal der/die/das counts per topic; every word needs a hand-drawn SVG in data/cocuk/resimler.json (no emoji). Run node scripts/check-kids-games.mjs (CI runs it). No account, form or server request; only the sound setting and best scores in localStorage (baKelimeOyunlari); sound plays the site's own MP3s first (data/cocuk/ses, list data/cocuk/sesler.json from node scripts/kids-audio.mjs; Thorsten-Voice CC0 + Coqui TTS Apache 2.0, see data/cocuk/ses/LISANS.md and scripts/cocuk-ses/README.md; never voices with a non-commercial licence), then on-device German voices only, and the game must stay silent without errors when there is none. New recordings need the teacher's listening approval.

Alphabet game (/almanca-alfabe/, docs/alfabe-oyunu.md): content in data/alfabe.json (two examples per letter, each containing its letter), logic in js/alfabe-logic.js (no DOM; child/adult differences only in PROFILES and css [data-profil] variables), UI in js/alfabe.js. Only on-device voices. Visitors: localStorage baAlfabe only; signed-in active students also sync to users/{uid}/progress/alfabe (js/account/alfabe-sync.js, best-value merge, deleted with the other student data). Pronunciations in plain Turkish letters without phonetic marks. Run npm run test:alfabe (CI), node tests/alfabe.mjs and npm run test:alfabe-account after changes.

Exam writing tasks (Schreiben, js/writing-task.js): sets in data/exams/<exam>/<level>/schreiben/teil-<n>/<set>.json with kind "writing", content points, a word target, a Turkish self-check list per exam criterion, Redemittel (de + tr) and an original model answer inside the word range (node scripts/check-exams.mjs; format in docs/sinav-setleri.md). Visitors never load Firebase; signed-in active students save to users/{uid}/writings (create-only, at most 4000 characters, at most 10 per 24 hours via users/{uid}/limits/writing), the teacher writes feedback. Writings and limits are deleted with the other student data (12 months after the last lesson). AI check (Aşama B, worker/schreiben-kontrol.js on Cloudflare Workers Free, docs/yapay-zeka-kurulum.md): only the text and the task name go to the model, never name, e-mail or uid; default mode 'draft' (aiDrafts, never readable by students, teacher approves); students under 16 need the separate parental AI consent (users.aiConsent); limits 3 per student and 600 site-wide per Berlin day (aiLimits). Never add anything that needs a paid plan or a card. Run npm run test:worker and npm run test:schreiben-ai after changes.

Run node scripts/check-grammar.mjs and browser checks for the lesson, correct exercise destination, mobile overflow, dark mode and deep links. New exercise topics require actual authored explanations; a card or placeholder is insufficient. data/grammar-legacy.json only records existing B1/B2 gaps and must not be expanded to bypass coverage.

Publish through the existing GitHub Pages workflow when the user has authorized publishing. Do not claim the coverage check writes educational content automatically or verifies email delivery.

Shared design tokens and components (colours, fonts, buttons, focus, header, footer, ba-* pieces) live in css/base.css; page stylesheets only add layout and must use the --ba-* tokens. Design skills live in .claude/skills (web-design-guidelines for UI audits, taste-skill for visual direction, redesign-existing-projects for upgrading existing pages). docs/design/claude-DESIGN.md is a reference design system from getdesign.md; use it for inspiration only and keep the site's existing theme, dark mode and Turkish learner focus unless the user asks for a redesign.

Languages (TR / EN / DE): the language is in the URL. Turkish pages stay at their root paths; English and German pages live under /en/ and /de/ with translated slugs (German slugs use ue/oe/ae/ss), are listed in scripts/site-pages.mjs TRANSLATIONS with "lang" and their Turkish page in "of", and keep their content in their own files (en/about/index.html). That list is the slug table: node scripts/build-pages.mjs writes the language buttons, menu/footer links, hreflang (tr, en, de, x-default), sitemap alternates and the route table in js/app.js and js/legacy-hash.js from it, and rewrites internal links in EN/DE pages to the translated page when one exists. Turkish pages without a translation (grammar lessons, blog) keep Turkish content; their menu and footer follow the chosen language and a dismissible "only in Turkish" note appears (js/app.js). German addresses the reader with "Sie" (pages and the interface dictionaries in js/app.js, js/account/i18n.js, js/placement.js); only the children's game Artikel Evleri (ae*, kidsCard*) uses "du". EN/DE pages mark links to Turkish-only content (grammar, exercises, blog) with "(in Turkish)" / "(auf Türkisch)". The EN/DE contact pages send "[EN]" / "[DE]" in the e-mail subject. Menu and footer labels live in the js/app.js dictionary. Run node tests/i18n.mjs (CI runs it; every page in every language, switcher, legacy #about links, 404 redirects, contact form messages and subject, "Sie", 390 px, dark mode, menu fit) after changing pages, translations or the header.
