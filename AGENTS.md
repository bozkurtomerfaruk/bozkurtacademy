# Exercise and grammar authoring

Every question needs feedback explaining its own grammatical trigger: the actual subject and verb form, required preposition/case, meaning clue or word-order constituents. Do not reuse a topic-level paragraph with only the correct answer substituted. Preserve useful existing reasoning and avoid stock instructions that bury it. Check incorrect multiple-choice and written submissions in the browser, including Enter submission, when changing feedback.

When adding an exercise topic at any level, also add its complete grammar lesson in the same task without asking the user separately. This is a standing user preference.

Use the exercise topic ID in data/<level>-grammar.json. Register a new level in data/grammar-index.json. The grammar list derives from data/catalog.json; do not maintain a separate topic list.

Write simple Turkish for a first-time learner, German examples with Turkish translations, progressing from simple to harder examples. Include useful accessible visual diagrams, at least five teaching sections, a summary and self-check, three FAQs, three relevant related topics, an exercise link, the existing author introduction and moderated name/email comment form. Large headings do not need final periods. Reuse the professional theme and dark-mode styles.

After adding or renaming exercise packages, run node scripts/build-search-index.mjs so the exercise search finds them (CI runs it with --check).

Word lists: questions may list their nouns in "vocab" (keys of data/sozluk.json: article + Turkish meaning, also shown in the German and English interface). New entries get "checked": false and stay hidden until the teacher sets "checked"; mark entries you are not sure about with "unsure": true (they are listed first). After changing vocab or the dictionary, run node scripts/sozluk.mjs to refresh docs/sozluk-kontrol.csv and docs/sozluk-bekleyen.csv, the table of words not yet checked that the teacher reviews for each pull request (CI runs it with --check). Skip Turkish hints, German instructions, grammar terms (Subjekt, Kasus, Hauptsatz …), names and imperatives; a word like Essen or Morgen counts as a noun only after an article or preposition. Exam sets never show word lists.

End-of-level tests: data/seviye-sonu/<level>.json, linked from data/catalog.json with "levelExam". 30 questions per attempt with a fixed topic distribution; the pool needs at least twice as many questions per topic, each with four options and its own Turkish explanation (node scripts/check-level-exams.mjs). Results go to results with topic "seviye-sonu" and topicErrors; never store which questions were shown.

Children's game Artikel Evleri (#artikel-evleri, js/artikel-evleri.js): topics in data/cocuk/artikel-evleri.json list keys of data/sozluk.json (checked, not unsure, one article) with equal der/die/das counts per topic; every word needs a hand-drawn SVG in data/cocuk/resimler.json (no emoji). Run node scripts/check-kids-games.mjs (CI runs it). No account, form or server request; only the sound setting and best scores in localStorage (baKelimeOyunlari); sound plays the site's own MP3s first (data/cocuk/ses, list data/cocuk/sesler.json from node scripts/kids-audio.mjs; Thorsten-Voice CC0 + Coqui TTS Apache 2.0, see data/cocuk/ses/LISANS.md and scripts/cocuk-ses/README.md; never voices with a non-commercial licence), then on-device German voices only, and the game must stay silent without errors when there is none. New recordings need the teacher's listening approval.

Alphabet game (/almanca-alfabe/, docs/alfabe-oyunu.md): content in data/alfabe.json (two examples per letter, each containing its letter), logic in js/alfabe-logic.js (no DOM; child/adult differences only in PROFILES and css [data-profil] variables), UI in js/alfabe.js. Sound: the site's own MP3s first (audio/alfabe/, list manifest.json), then on-device voices only; no speech service is called while playing. The MP3s are made with node scripts/generate-alfabe-audio.mjs: default provider 'yerel' (free, no card): Piper de_DE-thorsten-medium for German, Chatterbox Multilingual (MIT) for Turkish, Whisper picks the best of several takes; set up with scripts/alfabe-ses/kur.sh or kur.ps1, models in the untracked .tts-modeller/. Use only voices whose model, training data and base model all allow commercial use (see audio/alfabe/LISANS.md); letter names via data/alfabe.json sesMetni (Piper text or [[ phonemes ]]). Own recordings with the same file name win after --index; paid services (google, azure, elevenlabs) stay optional, keys only in the untracked .env. Visitors: localStorage baAlfabe only; signed-in active students also sync to users/{uid}/progress/alfabe (js/account/alfabe-sync.js, best-value merge, deleted with the other student data). Pronunciations in plain Turkish letters without phonetic marks. Run npm run test:alfabe and node scripts/generate-alfabe-audio.mjs --check (CI), node tests/alfabe.mjs and npm run test:alfabe-account after changes; new recordings need the teacher's listening approval (tools/audio-check.html).

Exam writing tasks (Schreiben, js/writing-task.js): sets in data/exams/<exam>/<level>/schreiben/teil-<n>/<set>.json with kind "writing", content points, a word target, a Turkish self-check list per exam criterion, Redemittel (de + tr) and an original model answer inside the word range (node scripts/check-exams.mjs; format in docs/sinav-setleri.md). Visitors never load Firebase; signed-in active students save to users/{uid}/writings (create-only, at most 4000 characters, at most 10 per 24 hours via users/{uid}/limits/writing), the teacher writes feedback. Writings and limits are deleted with the other student data (12 months after the last lesson). AI check (Aşama B, worker/schreiben-kontrol.js on Cloudflare Workers Free, docs/yapay-zeka-kurulum.md): only the text and the task name go to the model, never name, e-mail or uid; default mode 'instant': the Worker returns the feedback and writes aiFeedback, the student sees it on the task page (js/account/writing-feedback.js, label "Yapay zekâ geri bildirimi – nadiren hata yapabilir"), can flag an item (aiFlags) and resubmit a corrected version (revisionOf); the teacher counter (needsTeacher in js/account/teacher-common.js) only counts flagged items and writings the AI could not check (aiSkip: consent, limit, error); modes 'draft' (aiDrafts, never readable by students, teacher approves) and 'off' stay; students under 16 need the separate parental AI consent (users.aiConsent), and direct display needs consent version 2, otherwise the result goes to aiDrafts; limits 3 per student and 600 site-wide per Berlin day (aiLimits). Never add anything that needs a paid plan or a card. Run npm run test:worker and npm run test:schreiben-ai after changes. Whenever the prompt or cleanResult changes, also run node scripts/ai-deneme.mjs without a name (all sample texts of all exams in tests/ai-deneme/ against the real model; needs CF_ACCOUNT_ID and a temporary Workers AI token from the teacher, never stored in the repository) and record found/expected and unexpected items in docs/durum.md; add sample texts for every new exam. Trials share the Workers AI Free quota (10,000 Neurons per UTC day) with the students: at most 4,000 Neurons and 2 full rounds per day (scripts/ai-deneme-kota.mjs enforces this and stops before sending anything; --ids runs single texts); never work around the guard. Ask the teacher before every trial and run it only after approval, in the working session during the day; no scheduled or night trial tasks. Level-specific prompt notes go into the user message (LEVEL_NOTES in worker/schreiben-kontrol.js), never into the shared PROMPT: such lines changed the results of other exams.

Run node scripts/check-grammar.mjs and browser checks for the lesson, correct exercise destination, mobile overflow, dark mode and deep links. New exercise topics require actual authored explanations; a card or placeholder is insufficient. data/grammar-legacy.json only records existing B1/B2 gaps and must not be expanded to bypass coverage.

Publish through the existing GitHub Pages workflow when the user has authorized publishing. Do not claim the coverage check writes educational content automatically or verifies email delivery.

Shared design tokens and components (colours, fonts, buttons, focus, header, footer, ba-* pieces) live in css/base.css; page stylesheets only add layout and must use the --ba-* tokens. Design skills live in .claude/skills (web-design-guidelines for UI audits, taste-skill for visual direction, redesign-existing-projects for upgrading existing pages). docs/design/claude-DESIGN.md is a reference design system from getdesign.md; use it for inspiration only and keep the site's existing theme, dark mode and Turkish learner focus unless the user asks for a redesign.

Homework (Classroom layout): teacher list ogretmen-odevler.html, create/edit ogretmen-odev.html (?duzenle=<groupId>), student odevlerim.html (TR/DE/EN). One copy per student in users/{uid}/assignments with a shared groupId; format and legacy reading (docUrl → links, never rewritten except when the teacher edits) in js/account/assignments.js. Links http/https only, checked in the form (the teacher rule stays broad). PDFs go to the teacher's Google Drive (js/account/drive.js: Google Identity Services, drive.file scope only, folder "Bozkurt Academy Ödevler", anyone-with-link viewer, max 20 MB; emulator uses js/account/drive-mock.js, never live); never Firebase Storage. Run npm run test:odev and npm run test:csp after changes.

Homework emails: the Worker route POST /odev-bildirim (worker/schreiben-kontrol.js) verifies the teacher's Firebase ID token (TEACHER_UID), reads addresses, lang and the title from Firestore with that token (never trust addresses or text from the browser) and sends via Brevo (BREVO_API_KEY secret) from info@: only title, due date and the odevlerim.html link, never content, notes or names. One "new" email per copy (mailNewAt), "update" at most once per copy per Berlin day; max 100 per day (mailLimits/_global); opt-out users.homeworkMail; under-16 parent only via inviteParent. Setup: docs/odev-eposta-kurulum.md. Run npm run test:worker and npm run test:odev-eposta after changes.

Lesson notebook (Ders defteri, one-to-one lessons only): teacher page ogretmen-ders.html (?ogrenci=<uid>[&not=<id>][&ders=<lessonId>]), started from the student page ("Derse başla") or the calendar lesson dialog; student page ders-notlarim.html (TR/DE/EN, "du") and the panel section. Notes in users/{uid}/lessonNotes (format in js/account/lesson-notes.js): only the teacher writes, an approved student reads their own, live (onSnapshot); deleted with the other student data. Editor: Quill 2 vendored in js/vendor/quill (never a CDN); content always passes the allow-list in js/account/note-format.js (pasting and displaying); colours are palette classes with --ba-note-*/--ba-mark-* tokens. Autosave in js/account/autosave.js (1.5 s idle, at most 10 s, at least 2 s apart, flush on leave, local backup baDersDefteri:… until the server confirms); stay within the Spark free quota and keep notes under 1,000,000 bytes. Run npm run test:ders-defteri, npm test and npm run test:csp after changes.
